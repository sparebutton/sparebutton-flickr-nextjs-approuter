# ダッシュボード設定の協働パターン

2026-08-07、Cloudflare の Cache Rule 作成と API トークン発行、GitHub の Secrets 登録を通じて確立した進め方。

| 役割 | 担当 |
|---|---|
| 画面を開く・値を入力する・保存ボタンを押す | **ユーザー** |
| 入力すべき値と、その選択肢を選ぶ理由の提示 | Claude |
| 入力内容の検証（DOM から実際の選択値を読む） | Claude |
| 保存後の実挙動の検証（curl / API / ログ） | Claude |

**Why:** ユーザーは「〜のページを開きました」と状態だけ伝えてくる。ここで Claude が代行するのではなく**値と理由を出して本人に入力させ、押す前に検証する**のが噛み合う。スクリーンショットだけでは react-select の選択済み値とプレースホルダを見分けられないので、**DOM を読んで `.react-select__single-value` を確認する**のが確実（実際に「トークン名は入っているが権限は未選択」のような見落としを検出できる形になっている）。

**How to apply:**

- ラベルは実画面の文言に合わせる。ドキュメント上の一般名と UI の日本語表記はズレる（例: 「キャッシュ状態」ではなく「キャッシュの適格性」）
- 選択肢には**なぜそれを選ぶか**を 1 行添える。特に「これを選ばないと機能しない」「これを選ぶと元に戻せない」は明示する
- 選択肢が見つからないと言われたら、**推測せず実際にドロップダウンを開いて選択肢を列挙する**
- **認証情報（API トークン等）はチャットに貼らせない。** 発行画面から Secrets 画面へ直接コピーさせる
- 設定変更そのものは代行しない。ただし**検証のための読み取り操作（DOM 参照・ドロップダウンを開く）は行ってよい**
