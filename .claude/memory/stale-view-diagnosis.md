# 「本番は直っているのに直って見えない」の切り分け

2026-08-07、`ImageFadein` の修正をデプロイ済みなのに iPhone Safari でだけ画像がグレーのままという報告があった。原因はキャッシュではなく**開きっぱなしのタブ**だった。

## 3 つの容疑者と見分け方

| 容疑者 | 症状 | 判定方法 |
|---|---|---|
| 開きっぱなしのタブ | 特定の端末の特定のタブだけ古い。設定からキャッシュを消しても直らない | **リロードすると直る**。これが決め手 |
| Cloudflare エッジ | 全端末で古い。放置すると直る | `curl -sI <URL>` の `cf-cache-status` / `age` |
| ブラウザキャッシュ | 同一端末の全タブで古い | Vercel が `max-age=0, must-revalidate` を返すため通常は容疑者にならない |

**Why:** iOS の「履歴と Web サイトデータを消去」は**すでに開いているタブの DOM を作り直さない**。タブの中身は開いた時点の HTML のまま残り続ける。ユーザーが「キャッシュを消したのに直らない」と言うときはこれが最有力候補で、別ブラウザで開くと直るのも同じ理由（そちらは新規ロードだから）。

**How to apply:** まず**配信側が新しいことを確認する** — `curl` で本番 HTML を取得し、修正が入っているか grep する。入っていればエッジもブラウザも無罪で、残るのはタブなので**リロードを依頼する**。切り分け前に「キャッシュを消してください」と言わない（消しても直らず、原因特定が遅れる）。

デプロイとパージの実行時刻は `gh run list` で確認できる（[[cloudflare-cache-and-purge]] のパージ workflow の run が本番反映完了の目印になる）。
